# DEV-006 — Terminal Status Evidence Alignment

Status: PASS — REPOSITORY STATUS ALIGNMENT VERIFIED

## Objective

Resolve the documented DEV-005 limitation where the terminal `status` command reads `.status-main`, while the current website markup does not expose that selector.

The goal is to make the existing `status` command truthful and compatible with the current AMRHZ.SYS status surface, without inventing runtime health or adding backend capabilities.

## Evidence Basis

DEV-005 verified:

- terminal DOM-to-JavaScript wiring is corrected;
- existing command set remains intact;
- `status` is wired but currently depends on `.status-main`;
- `.status-main` is not present in the current page markup;
- the command therefore may return its existing `UNAVAILABLE` fallback.

## Scope

1. Re-inspect the current status markup and `script.js`.
2. Determine what status information is actually represented by existing repository/static evidence.
3. Align the `status` command with an existing truthful status source.
4. Preserve the distinction between static/documentary state and verified runtime health.
5. Keep the change browser-local and minimal.
6. Preserve all existing terminal commands and history behavior.
7. Test the source-level selector/data compatibility.
8. Document limitations.
9. Create a checkpoint only after PASS.

## Required Evidence

- exact current status markup;
- exact JavaScript status selector/data path;
- repository/static evidence supporting any displayed status;
- explicit limitation if runtime health remains unverified;
- source validation;
- repository-level test result.

## Acceptance Criteria

- [x] Current status markup re-inspected.
- [x] Current `status` command implementation re-inspected.
- [x] A truthful existing status source is identified.
- [x] `status` command no longer depends on a missing selector.
- [x] No runtime health claim is invented.
- [x] Existing terminal commands remain intact.
- [x] No unrelated website behavior is intentionally changed.
- [x] JavaScript source structure validated; browser syntax execution not independently run.
- [x] Repository-level status compatibility test passes.
- [x] Browser runtime verification explicitly marked as not independently verified.
- [x] Final state is documented.
- [x] Checkpoint created after PASS.

## Non-Goals

DEV-006 does not implement:

- backend health monitoring;
- live infrastructure telemetry;
- API health checks;
- authentication or authorization;
- AI model execution;
- autonomous agents;
- remote command execution;
- OS shell access;
- persistent terminal state;
- automatic promotion of static status into runtime status.

## Safety / Boundary

The terminal remains a browser interface only. The `status` command must report only information supported by observable website/repository evidence.

## Execution Order

`INSPECT → IMPLEMENT → TEST → PASS → CHECKPOINT`

Implementation must not begin until explicit approval is given.
