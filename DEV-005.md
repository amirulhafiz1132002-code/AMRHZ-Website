# DEV-005 — Terminal Wiring Correction

Status: LOCKED

## Objective

Correct the verified AMRHZ.SYS terminal HTML-to-JavaScript wiring mismatch identified by DEV-004, without expanding the terminal into a backend, AI execution layer, or autonomous system.

## Core Rule

`REAL STATE > UI SIMULATION`

The terminal may only be classified as functional after the required DOM structure, event wiring, command behavior, and tests provide evidence.

## Evidence Basis

DEV-004 established:

- terminal UI exists;
- terminal command logic exists;
- HTML and JavaScript selectors are incompatible;
- terminal state is currently PARTIAL;
- correction must be separately implemented and tested.

## Scope

1. Inspect the current terminal markup and JavaScript once more before modification.
2. Align the terminal DOM structure and identifiers with the existing JavaScript interaction layer.
3. Preserve the existing command set:
   - `help`
   - `status`
   - `projects`
   - `whoami`
   - `clear`
4. Preserve command history behavior where supported by the existing implementation.
5. Preserve same-page navigation and existing website behavior.
6. Do not invent runtime status or backend capabilities.
7. Add only the minimum markup/wiring required for the existing terminal logic to operate.
8. Test the corrected source and interaction wiring.
9. Record the resulting state and limitations.
10. Create a checkpoint only after PASS.

## Required Evidence

The implementation must be supported by:

- exact terminal DOM identifiers;
- form/input/output compatibility;
- JavaScript event listener compatibility;
- command dispatch compatibility;
- syntax validation;
- repository inspection after modification;
- explicit test result;
- environment and limitations.

## Acceptance Criteria

- [ ] Current terminal implementation re-inspected.
- [ ] HTML IDs match the JavaScript selectors.
- [ ] Required terminal form structure exists and matches the submit listener.
- [ ] Existing command set remains intact.
- [ ] Clear behavior remains intact.
- [ ] Command history wiring remains intact.
- [ ] No unrelated website behavior is changed.
- [ ] JavaScript syntax validation passes.
- [ ] Repository-level terminal wiring validation passes.
- [ ] Browser runtime verification is either performed or explicitly marked as not independently verified.
- [ ] Final state is documented.
- [ ] Checkpoint created after PASS.

## Non-Goals

DEV-005 does not implement:

- backend persistence
- authentication or authorization
- AI model execution
- autonomous agents
- orchestration runtime
- remote command execution
- shell access to the user's device
- external integrations
- runtime health monitoring
- terminal command execution outside the browser page

## Safety / Boundary

The terminal is a browser interface only. Its commands must remain local to the webpage and must not be presented as operating-system shell commands or privileged device access.

## Execution Order

`INSPECT → IMPLEMENT → TEST → PASS → CHECKPOINT`

No implementation should begin until the current source is inspected again.

## Failure-Safe Rule

If the existing JavaScript behavior conflicts with the intended website architecture, preserve the evidence and stop rather than silently expanding scope.

## Expected Outcome

A corrected browser terminal whose existing interaction logic is properly wired to its HTML surface, with a truthful state classification based on the available test evidence.
