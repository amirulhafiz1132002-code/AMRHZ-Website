# DEV-004 — Terminal Evidence & Interaction Verification

Status: PASS — VERIFICATION COMPLETE

## Objective

Verify the actual implementation state of the AMRHZ.SYS browser terminal by comparing its HTML structure with the JavaScript interaction layer, documenting evidence, and establishing the boundary between a static terminal interface and a functional browser interaction.

## Core Rule

`REAL STATE > UI SIMULATION`

A terminal-looking interface must not be treated as functional merely because it renders like a terminal.

## Audit Model

`TERMINAL CLAIM → HTML IMPLEMENTATION → JAVASCRIPT WIRING → TEST → RESULT → STATE / LIMITATION`

## Scope Completed

1. Inspected `index.html` terminal markup and identifiers.
2. Inspected `script.js` terminal selectors, event handlers, and intended commands.
3. Compared the two implementations for exact wiring compatibility.
4. Determined which terminal capabilities are supported by repository evidence.
5. Classified the current terminal as PARTIAL.
6. Documented the mismatch without silently correcting it.
7. Defined the correction boundary as a separate implementation task.
8. Completed repository-level verification.
9. Created `checkpoints/DEV-004-verification.md`.

## Verification Result

The repository evidence supports:

> The AMRHZ.SYS terminal is **PARTIAL**. It has a real static terminal UI and a real JavaScript command engine, but the current HTML and JavaScript interaction wiring are incompatible. Therefore terminal commands are not verified as functional from the current repository state.

This is an evidence conclusion, not a browser-runtime claim.

## Key Mismatches

- HTML `terminal-output` vs JavaScript `terminalOutput`
- HTML `terminal-input` vs JavaScript `terminalInput`
- no terminal form vs JavaScript `terminalForm`
- no clear button vs JavaScript `clearTerminal`
